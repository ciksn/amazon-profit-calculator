# 亚马逊商品款式自动归类设计

日期：2026-07-31

## 1. 目标

在现有亚马逊利润计算工具中增加独立的“款式归类”模块。模块读取卖家精灵或 H10 导出的同品类商品 Excel，根据人工定义的品类规则、每种款式的典型商品和典型图片，对剩余商品自动归类。

系统采用“本地轻量模型初筛 + 云端多模态模型复核 + 人工确认”的混合路线。目标是在每月 1,000–10,000 个商品的规模下，将人工复核比例控制在 10%–20%，人工修正后总体准确率达到 95%–98%。

款式判断以功能为优先依据；当品类功能相似时，再比较形状、结构、材质和图案。颜色默认不作为款式划分条件，除非某个品类明确覆盖此默认规则。

## 2. 已验证的数据前提

测试数据：

- H10 澳洲站导出：200 个唯一 ASIN，200 个商品链接完整。
- 卖家精灵美国站导出：8 条可用商品链接。

从两个站点抽取 18 个真实商品进行商品页访问测试：

- 18/18 成功取得商品页，未遇到验证码。
- 澳洲站平均取得 7.8 张图库图片，美国站平均取得 8.0 张。
- 17/18 个商品的导出主图与当前商品页主图一致。
- 1 个澳洲商品的当前页面主图已变化，说明系统必须处理导出滞后、变体切换或商品更新。

这组测试证明“通过 Excel 商品链接补齐商品图库”在当前样本上可行，但生产实现仍需要限流、重试、缓存、失败降级和持续成功率监控。

## 3. 范围

### 3.1 首版包含

- 识别并导入 H10、卖家精灵 Excel。
- 解析站点、ASIN、商品链接、导出主图、标题和可用参数。
- 从亚马逊商品页获取当前商品图库。
- 图片去重、压缩缓存和图片用途识别。
- 按品类维护款式规则、典型商品、典型图片和反例。
- 本地图片向量检索前三候选款式。
- 综合图片、标题、参数和 OCR 结果计算置信度。
- 仅对中等置信度商品调用云端多模态模型。
- 提供人工复核、新款候选和人工修正回流。
- 保存规则、样本和模型版本，支持回滚。
- 批量导出分类结果和处理状态。

### 3.2 首版不包含

- 训练大型自有视觉模型。
- 自动破解验证码或绕过亚马逊访问控制。
- 自动遍历全部父子变体。
- 默认按颜色拆分款式。
- 完全无人值守地建立正式新款。
- 长期保存亚马逊原始高清图。

## 4. 系统架构

系统拆分为六个边界清晰的单元。

### 4.1 导入与标准化

输入是 H10 或卖家精灵 Excel。导入器识别格式并输出统一商品记录：

- 来源格式与导入批次
- 站点
- ASIN、父 ASIN（若有）
- 商品链接
- 导出主图
- 标题、品牌、类目、参数
- 销量、销售额等排序字段（若有）

同一站点内按 ASIN 去重。不同导入批次保留来源记录，以便发现页面变化。

### 4.2 商品图片采集

采集器访问商品链接，只解析商品主图库容器，不扫描整页全部图片。输出当前主图、辅图和采集状态。

处理规则：

- 控制并发并在请求之间加入抖动。
- 首次失败后指数退避重试。
- 验证码、页面失效、地区限制和超时分别记录。
- 重试失败时退回 Excel 导出主图，并强制进入低置信度流程。
- 对比导出主图与当前主图；不一致时标记“页面已变化”并进入人工复核。
- 以站点、ASIN、图片标识和采集时间做缓存，避免重复访问。
- 只长期保存压缩缩略图与来源 URL；原始图片按短期缓存策略清理。

### 4.3 图片预处理

预处理器负责：

- 按图像感知哈希和向量相似度去重。
- 过滤视频播放封面、透明占位图和无关小图。
- 统一方向、色彩空间和推理尺寸。
- 识别图片用途：主图/整体图、结构图、功能细节图、尺寸图、场景图、无关图或未知。
- 对含文字图片运行本地 OCR，保留文字及位置。

一张图片可以拥有多个用途标签，例如“结构图 + 尺寸图”。无法判断时保留“未知”，不强行分配。

### 4.4 品类款式规则库

每个品类独立配置：

- 判断优先级，例如“功能 > 结构 > 材质 > 图案，忽略颜色”。
- 图片类型权重。
- 特征词、同义词和否定词。
- 款式列表及定义。

每种款式保存：

- 款式名称和文字定义。
- 3–10 个典型商品及其多张图片。
- 必须具备的功能或结构。
- 明确排除的特征。
- 容易混淆的相邻款式。
- 1–3 个典型反例。

典型单位是“商品”，不是孤立图片，以保留同一商品的整体、结构和功能证据。

### 4.5 自动分类引擎

分类分两阶段。

第一阶段使用本地 SigLIP2 小型模型生成图片向量：

- 分别比较每张待分类图片和典型图片。
- 每种款式取最相似若干张图片的加权平均，不允许单张偶然相似图决定结果。
- 结合图片用途权重，选出前三候选款式。
- 与全部款式都不相似时标记“疑似新款”。

第二阶段综合：

- 图片相似度。
- 标题和参数中的功能、结构、材质及图案词。
- OCR 提取的功能和尺寸信息。
- 必须特征是否出现。
- 排除特征是否出现。
- 同一商品的多张图片是否互相冲突。

系统必须保存分项分数、证据和冲突理由，不能只保存最终标签。

默认证据权重：

| 证据 | 默认权重 |
| --- | ---: |
| 功能细节图 | 30% |
| 结构图 | 25% |
| 主图/整体图 | 20% |
| 标题、参数及 OCR 文字 | 20% |
| 材质和图案 | 5% |
| 颜色和纯场景背景 | 0% |

这些权重是品类级配置，不是写死的全局常量。

### 4.6 人工复核工作台

复核页面一次显示一个商品：

- 按图片用途分组的全部商品图。
- 标题、参数和 OCR 结果。
- 前三候选款式及典型商品。
- 支持和反对每个候选的证据。
- 本地模型与云端模型结论。
- 置信度、分数差和冲突原因。

操作包括：

- 确认系统结果。
- 改为其他已有款式。
- 标记疑似新款。
- 标记图片不足或无法判断。
- 忽略无效商品。

复核队列默认优先显示高销量商品、结论冲突、主图变化、疑似新款和低置信度商品。

## 5. 置信度分流

首版使用可解释规则，后续根据验证集校准：

### 5.1 高置信度

条件：

- 总分不低于 85。
- 第一名领先第二名不低于 15 分。
- 没有关键特征冲突。

处理：

- 自动归类。
- 随机抽查 5%。

### 5.2 中置信度

条件：

- 总分 65–84；或
- 第一名领先第二名 5–14 分。

处理：

- 将压缩后的代表性多图、标题、参数、品类规则和前三候选发送给云端多模态模型。
- 只有本地与云端结论一致且综合置信度不低于 80 时自动通过。
- 其他情况进入人工复核。

### 5.3 低置信度

条件：

- 总分低于 65；或
- 前两名差距小于 5 分；或
- 关键图片缺失；或
- 多张图片结论冲突；或
- 导出主图与当前主图不一致。

处理：

- 直接人工复核，不调用云端模型。

### 5.4 疑似新款

与全部已有款式都不相似，或出现现有规则不能解释的新功能时，进入新款候选池。

系统对候选做聚类：

- 第一次出现只保存为已审核案例。
- 同类案例达到 3 个时建议加入典型样本或扩充规则。
- 达到 5 个且存在清晰共同特征时建议建立新款。
- 新款和新增典型样本必须由人工确认。

## 6. 人工修正与模型学习

人工修正可以用于模型优化，但按风险从低到高分三层进行。

### 6.1 阈值与证据权重校准

每次修正都进入带版本的审核样本库。系统定期在训练集上寻找更合适的：

- 各图片用途权重。
- 文本、OCR 和图片证据权重。
- 高、中、低置信度阈值。
- 第一名与第二名的安全分差。

新配置必须在独立验证集上提高自动通过准确率，且不能让人工复核率超过目标，才允许发布。

### 6.2 典型样本中心更新

人工确认的商品用于更新款式向量中心和难例集合：

- 只有审核通过的商品可进入样本库。
- 新样本先进入候选区。
- 同类可靠案例累计 3 个后，系统建议加入正式典型样本。
- 对容易混淆的商品保存为“难例”或反例。
- 样本库变更需要人工确认并生成新版本。

这一步不修改基础模型参数，几十条高质量修正即可产生效果，是默认持续学习方式。

### 6.3 轻量参数微调

只有在单个品类累计约 300–500 条可靠修正，并且规则、阈值和样本中心更新仍不能解决稳定错误时，才启用参数微调。

首选：

- 在冻结的图像编码器上训练小型线性分类头；或
- 对轻量模型做 LoRA/Adapter 微调。

不首选全量模型训练。

发布门槛：

- 按品类划分训练集、验证集和锁定测试集。
- 新模型必须在锁定测试集上提高 Top-1 准确率或自动通过覆盖率。
- 每种款式不能出现明显准确率退化。
- 人工复核比例不能恶化超过设定容差。
- 模型、训练数据快照和参数均需版本化。
- 支持一键回滚到上一个稳定版本。

## 7. 数据与版本设计

核心实体：

- 导入批次
- 商品
- 商品页面快照
- 商品图片
- 图片用途与 OCR 结果
- 品类规则
- 款式
- 典型商品与反例
- 图片向量
- 分类运行
- 候选款式与分项证据
- 云端复核结果
- 人工审核记录
- 模型、规则和样本版本

分类结果必须记录当时使用的模型版本、规则版本和样本版本，确保以后能够复现。

## 8. 错误处理与降级

- Excel 格式无法识别：拒绝导入并显示缺失字段。
- 单行数据不完整：跳过该行并生成错误报告，不中止整批。
- 商品页暂时失败：重试并使用缓存。
- 商品页永久失败：仅使用导出主图和文本，强制人工复核。
- 图片下载失败：保留其他图片，记录缺失比例。
- OCR 失败：忽略 OCR 证据，不中止分类。
- 本地模型失败：暂停当前批次，不直接将全部商品送往云端。
- 云端超时或限流：进入待重试队列；超过次数后转人工。
- 规则或模型升级：新批次使用新版本，历史结果不自动覆盖。
- 批量任务中断：按商品保存检查点，支持断点续跑。

## 9. 实施阶段与验收

### 9.1 阶段一：取图与人工基准集

预计 5–7 个开发日。

选择 2–3 个代表性品类，每个品类人工标注 200–400 个商品。

验收：

- 首次取图成功率不低于 90%。
- 重试后成功率不低于 95%。
- 无关图片误收率不高于 5%。
- 每个正式款式至少 3 个典型商品。
- 形成不少于 500 个已审核商品的基准集。

取图成功率未达到 90% 时，不进入模型阶段。

### 9.2 阶段二：本地初筛原型

预计 5–8 个开发日。

验收：

- 500 个商品约 10–40 分钟完成，具体取决于硬件和下载速度。
- Top-3 召回率不低于 92%。
- 高置信度自动归类覆盖率达到 50%–70%。
- 高置信度部分准确率不低于 88%。

### 9.3 阶段三：云端复核与人工工作台

预计 7–10 个开发日。

验收：

- 80%–90% 的商品无需人工处理。
- 人工复核比例为 10%–20%。
- 自动直接通过部分准确率为 88%–94%。
- 人工修正后总体准确率为 95%–98%。
- 单件人工审核耗时约 15–30 秒。

### 9.4 阶段四：稳定性与持续优化

预计 5–10 个开发日，可在实际使用中逐步完成。

包括断点续跑、缓存管理、并发限制、批量改款、审计、版本回滚、结果导出和新款候选聚类。

## 10. 成本

按每月 1,000–10,000 个商品、每个商品 6–8 张有效图估算：

| 项目 | 月成本估算 |
| --- | ---: |
| 本地向量计算 | ¥0–100 |
| 云端多模态复核 | ¥20–200 |
| 本地 OCR | 约 ¥0 |
| 图片缓存 | ¥0–50 |
| 代理或第三方采集兜底 | 初期 ¥0，必要时 ¥100–500 |
| 人工审核 | 约 1–12 小时 |

在现有工具中开发，预计总工作量 22–35 个开发日。

外部开发参考：

- 可验证原型：约 2–4 万元。
- 完整可用版本：约 5–10 万元。
- 含生产部署、权限和长期维护：约 8–15 万元。

## 11. 测试与准确率口径

准确率按商品计算，不按单张图片计算。

基准数据划分：

- 60%：典型样本和规则建设。
- 20%：阈值与权重调整。
- 20%：锁定测试集，调参期间不得查看答案。

持续记录：

- Top-1 准确率。
- Top-3 召回率。
- 自动通过覆盖率。
- 自动通过准确率。
- 人工复核比例。
- 新款发现召回率。
- 每个品类、每种款式的准确率和召回率。
- 商品页获取成功率和图片误收率。

正式上线门槛：

- Top-3 召回率不低于 92%。
- 自动通过准确率不低于 90%。
- 人工复核比例不高于 20%。
- 人工修正后总体准确率不低于 96%。
- 连续三批数据没有明显下降。

未达到标准的品类单独降级为“多人工模式”，不影响其他品类。

## 12. 推荐技术组件

- 现有 Node.js 服务继续负责 Excel 导入、任务编排、页面和数据库。
- 独立的 Python 推理进程负责 SigLIP2、OCR、图片预处理和可选微调。
- SigLIP2 小型模型作为首版本地视觉编码器。
- 本地 OCR 使用 PaddleOCR 或同等级轻量方案。
- PostgreSQL 保存业务记录、审核和版本信息。
- 向量规模较小时直接保存向量并在应用层计算；规模增长后再引入 pgvector，首版不提前增加依赖。
- 云端多模态模型通过统一适配器接入，允许在 Gemini 和 OpenAI 之间切换。

## 13. 安全与合规约束

- 遵守亚马逊站点的访问规则和适用条款。
- 不实现验证码绕过。
- 图片只用于内部商品分类，不作为对外图库发布。
- 云端复核只上传分类所需的压缩图片和最少文本。
- API 密钥保存在服务端环境配置中，不进入浏览器和导出文件。
- 对外部模型保存请求版本和结果摘要，但不记录密钥或敏感请求头。
