# 同款竞品卖点分析与评论解析兼容设计

## 目标

修复 Amazon 新版商品详情页 Top Reviews 无法提取的问题，并在卡片版同款竞品中加入与普通竞品一致的卖点分析能力。同时扩展同款竞品复制结果，加入 A+、视频和卖点列。

## 评论解析

- 继续只读取 Amazon 商品详情页公开显示的 Top Reviews，不进入全部评论页。
- 评论根节点继续使用 `data-hook="review"`。
- 正文同时兼容旧版 `review-body` 和新版 `reviewText`。
- 标题同时兼容旧版 `review-title` 和新版 `reviewTitle`。
- 继续解析星级、日期、Verified Purchase、Vine 和 helpful 数量。
- 按评论 ID 或规范化正文去重，最多保存 10 条。
- 保留现有 Amazon 域名、商品路径、重定向、超时、页面体积和验证码限制。
- 页面抓取失败时继续使用 Gemini URL Context；不得绕过登录或验证码。

## 同款竞品卖点分析

- 普通竞品和同款竞品共用现有卖点抓取及 Gemini 分析服务。
- 新增同款竞品卖点分析接口，接口路径为：
  - `POST /api/projects/:id/similar-competitors/analyze`
- 请求体沿用 `{ "country_code": "US" }`，也支持现有 `manual_rows` 手动五点补充格式。
- 接口只查询 `competitor_kind = 'similar'` 的当前站点月销售额前 5 名。
- 已有合规卖点的同款竞品跳过，仅处理未完成项或指定的手动补充项。
- 分析结果继续写入 `feature_bullets`、`selling_points`、`differentiation` 及现有分析状态字段。
- 普通竞品和同款竞品的查询、重试、手动补充及结果互不污染。

## 卡片界面

- 同款竞品站点操作区新增“卖点分析”按钮。
- 同款竞品表在“评价数量”后、“评论分析”前新增“卖点分析”列。
- 行内展示沿用普通竞品的紧凑文本样式和完整内容提示。
- 分析失败时允许使用现有手动五点弹窗补充，同款弹窗提交到同款接口。
- 按钮状态沿用普通竞品：分析中、卖点分析；已完成项不会重复分析。

## 同款竞品复制结果

复制列固定为：

1. 图片
2. 链接
3. 是否有 A+
4. 是否有视频
5. 售价
6. 销售额
7. 利润率
8. 上架时间
9. 评分
10. 评价数量
11. 卖点分析
12. 评论优点
13. 评论缺点

数据规则：

- 卖家精灵 Excel 提供 A+ 或视频字段时，复制为“是”或“否”。
- H10 未提供对应字段时，复制为空白，不输出破折号。
- 卖点分析使用现有 `competitorAnalysisText` 结果。
- 未完成的卖点、评论优点或评论缺点按现有规则输出空白或待分析文本；A+/视频缺失必须为空白。
- A+ 和视频仅加入复制结果，不增加同款竞品页面表格列。

## 测试与部署

- 新增 Amazon 新版 `reviewText`、`reviewTitle` HTML 提取测试，并保留旧版结构测试。
- API 测试覆盖同款接口只选择同款前 5、已完成跳过、手动补充和普通/同款隔离。
- 前端测试覆盖同款卖点按钮、表格列位置以及 13 列复制顺序。
- 测试卖家精灵 A+/视频输出“是/否”，H10 缺失时为空白。
- 运行 `npm test`、`npm run test:coverage`、`npm run build:pages`。
- 部署前备份韩国 PostgreSQL，更新服务文件并重建 Docker 应用，验证数据库、接口和公网静态资源。

## 非目标

- 不在同款竞品页面表格中显示 A+ 或视频列。
- 不抓取全部评论页。
- 不刷新或覆盖已经成功保存的评论分析结果。
- 不改变现有普通竞品接口路径。
